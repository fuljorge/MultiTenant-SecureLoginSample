# Contract: Control Plane identity API

Contract view for review. The source of truth in the implementation is the OpenAPI
generated by FastAPI, and the TypeScript client is generated from it (stack §3.1).

## Conventions

- Base: `/api/v1`. Same domain as the Studio (a `__Host-` cookie does not accept a subdomain).
- Authentication: BFF session cookie. State-changing requests require the
  `X-CSRF-Token` header.
- Authorization: each route declares the required permission (spec matrix, section 5.1),
  evaluated against the role in the **active organization**. No session: `401`. No
  permission: `403` and an `access.denied` event in the Audit Trail.
- Resources from another organization return `404` (they do not reveal existence); an
  attempt on a person from another organization is recorded as `access.denied` (US5,
  scenario 8).
- Errors use the *Problem Details* format (RFC 9457), with no sensitive data.
- **Recent re-authentication (RF-031):** routes marked "recent" require a full login
  (password and code) no older than 15 min. Otherwise: `401` with
  `{"code": "reauth_required"}`, with no effect; the Studio sends the person to
  `GET /auth/login?reauth=1&return_to=...`.
- Concurrent editing: `If-Match` with the resource version; a mismatch returns `412`.

## Authentication and session (BFF)

| Method and route | Who | Description |
|---|---|---|
| `GET /auth/login` | public | Starts the OIDC flow (Authorization Code + PKCE) and redirects to Keycloak; with `reauth=1`, sends `prompt=login` and `max_age=0` (RF-031) |
| `GET /auth/callback` | public | Receives the code, creates the session, sets the cookie, activates the invitation's `pending` memberships and redirects to the Studio |
| `POST /auth/logout` | session | Ends the session in the BFF and in Keycloak |
| `POST /auth/backchannel-logout` | Keycloak | *Back-channel logout* (signed logout token); ends the BFF sessions linked to the Keycloak session |
| `GET /me` | session | User, principal type (`member` or `super_admin`), organizations with the role in each, active organization (null for the Super Administrator), effective permissions, CSRF token |
| `PUT /me/active-organization` | session | Switches the active organization (RF-019); validates the membership |
| `GET /me/sessions` | session | The user's active sessions (start, last use, browser, partial IP) |
| `DELETE /me/sessions/{id}` | session | Ends one of the user's own sessions |
| `GET /auth/password` | session | Redirects to the password change in Keycloak (*required action* `UPDATE_PASSWORD` via `kc_action`), always with a new authentication (`max_age=0`; RF-031) |

Password recovery and code login are Keycloak screens; they do not go through the API.

## Users

| Method and route | Permission | Description |
|---|---|---|
| `GET /users` | `users:read` | List with filters: name, e-mail, organization, role, status; pagination |
| `GET /users/{id}` | `users:read` | Detail with memberships and lockout status |
| `POST /invitations` | `users:manage` | Invites: `email`, `name`, `organization_id`, `profile` |
| `GET /invitations` | `users:read` | The organization's invitations |
| `DELETE /invitations/{id}` | `users:manage` | Revokes a pending invitation |
| `POST /invitations/{token}/accept` | session | Invitation acceptance by an already registered person |
| `PATCH /users/{id}/memberships/{org_id}` | `users:manage` | Changes the role in the organization |
| `DELETE /users/{id}/memberships/{org_id}` | `users:manage` · recent | Removes from the organization |
| `POST /users/{id}/disable` | `users:manage` · recent | Disables the membership in the active organization and ends the sessions in it; with no other active membership, also disables the account in Keycloak (RF-011; plan, section 4.4) |
| `POST /users/{id}/enable` | `users:manage` · recent | Re-enables the membership (and the account, if it was disabled) |
| `POST /users/{id}/email-change` | `users:manage` · recent | Starts an e-mail change; sends a confirmation to the new e-mail |
| `POST /email-change/{token}/confirm` | public | Confirms; updates Keycloak, ends sessions, notifies the old e-mail |
| `POST /users/{id}/sessions/revoke` | `users:manage` · recent | Ends all of the user's sessions |

An organization Administrator only acts on memberships of their own organization.
Changing the e-mail of someone who belongs to other organizations is rejected (`409`) in
this phase. Disabling or removing the last active Administrator of an active organization
returns `409` (RF-012). User routes return `403` for the Super Administrator (RF-028).

## Organizations (Super Administrator)

| Method and route | Permission | Description |
|---|---|---|
| `GET /organizations` | `organizations:manage` | All organizations: `q` (organization name or Administrator name/e-mail), `org_status`, `limit`, `offset` (RF-025) |
| `GET /organizations/{id}` | `organizations:manage` | Detail with Administrators and pending invitation |
| `POST /organizations` | `organizations:manage` · recent | Organization invitation: `name`, `admin_name`, `admin_email`; creates the organization as `pending` (RF-018) |
| `PATCH /organizations/{id}` | `organizations:manage` | Renames (`If-Match`) |
| `POST /organizations/{id}/suspend` | `organizations:manage` · recent | Suspends: ends sessions and blocks access (RF-026) |
| `POST /organizations/{id}/reactivate` | `organizations:manage` · recent | Reactivates |
| `POST /organizations/{id}/invitation/resend` | `organizations:manage` | Resends the pending organization's invitation |
| `POST /organizations/{id}/cancel` | `organizations:manage` · recent | Cancels a `pending` organization |
| `POST /organizations/{id}/administrators` | `organization_admins:manage` · recent | Invites one more Administrator: `name`, `email` (RF-027) |
| `POST /organizations/{id}/administrators/{user_id}/disable` | `organization_admins:manage` · recent | Disables the Administrator membership; `409` if it is the last active one (RF-012) |
| `POST /organizations/{id}/administrators/{user_id}/enable` | `organization_admins:manage` · recent | Re-enables |

A member's own organizations: `GET /me`.

|---|---|---|

## Security settings

| Method and route | Permission | Description |
|---|---|---|
| `GET /security-settings` | `security:manage` (Super Administrator) | Password policy, session timeouts, lockout, code parameters, validity of invitations and of activation and recovery links |
| `PUT /security-settings` | `security:manage` (Super Administrator) · recent | Applies to the Keycloak realm via the Admin API, within minimum security limits |

Minimum limits the API does not allow to be relaxed: password ≥ 12 characters; code ≥ 6
digits and validity ≤ 15 min; at most 10 attempts before lockout; maximum session ≤ 24 h.

## Audit

| Method and route | Permission | Description |
|---|---|---|
| `GET /audit-events` | `audit:read` or `audit:read:installation` | Filters: `q` (name or e-mail of the person, actor or target), `user_id`, `event_type`, `result`, `date_from`, `date_to`; `limit` (up to 200) and `offset`. Scope in [data-model.md](../data-model.md#who-reads-the-audit-trail-us6-scenario-2) |
| `POST /audit-events/export` | `audit:read` or `audit:read:installation` · recent | Same filters in the body; CSV with up to 10,000 rows, cells protected against formulas; records `audit.exported` (the `q` text is not stored) |

## Operations tool (outside the public API)

`cap-admin` CLI, run by the operations pipeline inside the customer's cluster, never
exposed over the network:

| Command | Use |
|---|---|
| `cap-admin bootstrap-super-admin --email --name` | Provisioning: creates the initial Super Administrator and sends the welcome e-mail (§53.2); does not create an organization |
| `cap-admin anonymize-user --email --ticket` | Right-to-be-forgotten request (LGPD): deletes the Keycloak account and the sessions, anonymizes name, e-mail, invitations and e-mail changes, removes IP and browser from the person's events; rejects the last active Super Administrator or Administrator (RF-012) |
| `cap-admin audit verify` | Recomputes the Audit Trail hash chain; exits with code 2 and the `seq` of the first tampered record |
| `cap-admin reissue-activation --email [--new-email]` | Support: reissues a Super Administrator's activation link, including to a new e-mail (spec edge case) |

Every run records an event with `actor_kind = support` and the ticket number.
